## 1. 当前主线结论

当前主线已经固定为：

- 角色：`IRONCLAD`
- 训练方式：`hybrid`，`pipe-binary`，`multi_process = true`
- 环境数：`4 env`
- 每轮采样：`episodes_per_iter = 160`
- 主线策略：`no-MCTS`
- 节奏：`save-interval = 5`

当前最重要的判断：

1. 多进程 worker 权重同步已经修好，训练现在是可信的。
2. `Act1 no-elite + 路线规划 + boss 条件化卡奖 + combat safety rerank` 能稳定把更多局送到 boss。
3. 当前仍然没有稳定通关，主瓶颈仍然是：
   - build coherence 不够
   - boss-ready 构筑不够
   - `combat_pending_stall` 仍有污染
4. 另外还确认了一条环境问题：
   - `Act1 boss -> Act2` 过渡曾经会过早落到 map，导致没有正确体现回血/后续结算
   - 该修复已经落代码，但需要下一次重启 host / 训练后才会真正生效

### 2.2 当前主线的关键在线策略

#### 非战斗

- 非战斗仍然以逐屏 PPO 为主。
- Act1 地图选择已经不是纯 PPO：
  - 先做 `Act1` 路线规划
  - 路线规划已经从“只避 elite”升级成：
    - 避开强制 elite
    - 优先 shop / rest
    - 结合后续节点价值打分
- 商店现在有一个明确硬规则：
  - 只要能删牌，优先删牌
  - 删牌优先级：`STRIKE_IRONCLAD -> DEFEND_IRONCLAD -> BASH`
- 卡奖现在有 boss 条件化 rerank：
  - 至少区分 `Soul Fysh` 和 `Waterfall Giant`
  - 结合 `skada boss_best_cards` 和手写 prefer / avoid

#### 战斗

- 战斗仍以 combat PPO 为主。
- 当前已接入 `combat safety rerank`：
  - 在低血 / 高 incoming 的局面，压制明显贪 setup、低即时收益的动作
- `combat_pending` 已经不是单纯盲 `wait`：
  - 现在会先 refresh
  - 再少量 wait
  - 并落更细的 debug 结构化日志

#### collector / worker

- 多进程 collector worker 每个 iter 都会 refresh 最新权重。
- ORT / worker refresh 路径已经修复，不再长期拿启动时旧模型 rollout。

### 7.4 当前对“最新训练问题”的判断口径

在已经吃到修复的新窗口里，当前最值得继续追的不是环境尾声，而是下面四类：

1. boss-ready build 仍不够：
   - 旧窗口 `2271-2275` 中，`boss_reach_rate = 42.75%`
   - 但 `act1_clear_rate = 1.38%`
   - 且有 `158` 个 `high_hp_boss_loss`
   - 说明不是单纯残血进 boss，而是构筑质量不够稳定
2. `Waterfall Giant` 仍然是专项短板：
   - `2271-2275` 的 `11` 个 `act1_clear` 中，`10` 个来自 `Soul Fysh`
   - `Waterfall Giant` 明显更难，值得单独做 card reward / build case mining
3. shop / campfire 资源转化偏弱：
   - `affordable_shop_skip` 仍高
   - clear run 的 `remove` 频率仍不高
   - campfire 仍几乎全是 `rest`，`smith` 偏少
4. 战斗压制窗口仍有损失：
   - `buff_window_no_pressure`
   - `low_hp_setup_action`
   - `death_on_end_turn_with_defeat`
   这几类模式仍然说明 combat policy 会在该抢 tempo 时做偏贪动作

### 7.5 仍然值得继续做的优化

- 把 build coherence 做成显式 scorer，而不是只靠单卡偏好
- 继续强化 shop / remove / potion / card reward 的统一 build 价值函数
- 继续扩展 `summary.json` 的可解释字段，尤其是 shop / card reward / boss case

- 单独跟踪 campfire `smith` 的收益，避免继续被 `rest` 吞掉长期强度

## 8. 典型复盘命令

### 7.6 非战斗离线锚点命名与后续实验梯度

命名口径统一为 `offline_noncombat_ranking`：

- 对外文档、目录、脚本入口、后续实验说明，统一使用 `offline_noncombat_ranking`
- `matchup` 只保留为历史兼容名，不再作为新实验和新数据集的主命名
- 当前代码里如果看到 `matchup_*`，应理解为 legacy internal name

当前决定：

- 新的离线非战斗排序数据，直接基于最新主线 checkpoint 派生
- 不优先复用老的 `matchup_bridge` 作为主数据源；它可以保留为补充对照，但不再作为主命名
- 当前首个派生基线以 `hybrid_02290.pt` 为起点

建议按下面梯度逐轮做，不要一次叠太多：

1. 先只生成最新 checkpoint 的 `offline_noncombat_ranking` 数据，不改训练权重
2. 第一轮只开很小的 `offline_noncombat_ranking_loss_weight`
   - 建议 `0.02 ~ 0.05`
   - 先不打开 `matchup_blend_beta`
   - 先不打开 `counterfactual_scoring`
3. 第二轮如果 `card_reward_skip_rate / affordable_shop_skip / empty_shop_leave` 有改善，再考虑增加
   - `offline_noncombat_ranking_updates_per_iter`
   - 不要先加大 loss weight
4. 第三轮再考虑 campfire / event 的额外轻量 rerank 或更强的局部奖励
5. `counterfactual_scoring` 放到更后面
   - 它更重，也依赖 `use_segment_collector`
   - 应当在离线非战斗锚点已经验证有效后再开

当前认为最适合优先验证的优化项：

- `offline_noncombat_ranking` 小权重恢复
- shop 仍保留现有 remove override，不额外加新硬规则
- 先观察 card reward / shop 的动作分布是否回稳
- campfire 先不加重规则，只做 replay 挖掘

当前不建议和离线锚点同轮叠加的项：

- `counterfactual_scoring`
- `matchup_blend_beta > 0`
- campfire 强规则
- shop 大范围手工打分替代 PPO
