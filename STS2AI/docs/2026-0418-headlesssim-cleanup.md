2026-0418 HeadlessSim 目录清理与主链收口

# 目标

把 `STS2AI/ENV/Sim` 收口到当前真实在用的主链：

- `HeadlessSim.csproj`
- `SrcCompat`
- `GodotSharpStub`
- `scripts/{scan_headless_ui_risks,generate_headless_model_compats,stub_generator}`

同时下线已经不参与构建或已经与当前目录结构脱节的历史残留，避免后续误用。

# 本轮清理

## 1. 下线 runtime Harmony 死代码

当前 headless 兼容不再依赖 runtime Harmony patch，而是依赖 `SrcCompat` 的源码级覆盖。

因此已移除：

- `STS2AI/ENV/Sim/HeadlessSim/HeadlessHarmonyBootstrap.cs`
- `Program.cs` 中对 `ApplyPatches()` 的启动调用

这次变更不改变运行语义，因为原先 `ApplyPatches()` 已经是 no-op。

补充：

- `Lib.Harmony` 仍保留在 `HeadlessSim.csproj`
- 目的只是满足上游 `src/Core/Modding/ModManager.cs` 的编译依赖
- 当前 HeadlessSim 主链不再依赖我们自己的 runtime Harmony patch

## 2. 移除已不参与构建的本地 UI shim

已移除：

- `STS2AI/ENV/Sim/HeadlessSim/Simulation/FullRunUiShim.cs`

该文件此前已被 `HeadlessSim.csproj` 显式排除，不参与当前构建。

## 3. 下线旧 stub/debug 脚本链路

已移除：

- `analyze_errors.py`
- `analyze_v2.py`
- `auto_fix_loop.py`
- `auto_stub.py`
- `dedup_stubs.py`
- `find_missing_usings.py`
- `fix_return_types.py`
- `fix_stubs.py`
- `gen_excludes.py`
- `gen_members.py`
- `gen_missing_stubs.py`
- `postfix_stubs.py`
- `excludes.xml`
- `build_output.txt`
- `error_files.txt`

这些脚本的共同问题是：

- 依赖旧的 `build_output.txt` 人工日志流
- 指向已经废弃的 `AutoGeneratedStubs.cs` / `AutoFixPatches.cs`
- 没有接入当前 `HeadlessSim.csproj + SrcCompat` 主链

## 4. 修正保留脚本的当前输出路径

保留的 `stub_generator.py` 已修正为输出到当前路径：

- `STS2AI/ENV/Sim/HeadlessSim/GeneratedStubs.cs`

不再写入旧的 `Runtime/HeadlessSim` 目录。

## 5. 清理越界文档

已移除：

- `STS2AI/ENV/Sim/解释.md`

`ENV/Sim` 目录下现在只保留 `README.md` 作为近端说明；正式说明文档统一放回 `STS2AI/docs`。

# 结论

清理后的 `ENV/Sim` 目录只保留当前会影响构建、compat 生成和风险扫描的代码与脚本；历史残留链路已经下线。

后续如果新增脚本，默认要求满足两点：

1. 直接面向 `HeadlessSim.csproj` 当前目录结构
2. 不依赖一次性人工 build 日志作为主输入
