2026-0418 HeadlessSim 0.103.2 兼容收口与验收

# 目标

把 `STS2AI/ENV/Sim` 收敛到“上游源码直编 + 少量源码级 compat + 少量核心 fork + runtime stub”这条可维护路线，并把 `headless-pipe` / `headless-binary` 两条协议都验收到可用。

# 当前结构

## 1. 继续保留核心 fork 的文件

这些文件和 pure-sim 主循环、mid-combat save/load、headless prompt 语义强耦合，当前不适合只靠 Harmony patch：

- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Combat/CombatManager.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Rooms/CombatRoom.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Saves/Runs/SerializableRoom.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Commands/CardPileCmd.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Commands/CardSelectCmd.cs`

这些 fork 已经做过定向 rebase，不再是旧版 compat 直接续命。当前保留的核心差异主要是：

- `CombatManager` 的 pure-sim turn transition、pending transition、headless/presentation 分支
- `CombatRoom` / `SerializableRoom` 的 mid-combat save/load 语义
- `CardPileCmd` / `CardSelectCmd` 的 headless prompt / selector 语义

## 2. 当前保留为源码级 compat 覆盖的文件

这类问题本质上更适合“host 编译时覆盖上游文件”，而不是运行时 patch：

- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Assets/PreloadManager.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Localization/LocString.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Models/Relics/Shuriken.cs`

说明：

- `PreloadManager`：headless 下跳过/容错资源加载更稳，避免 scene-side asset getter 抛异常。
- `LocString`：`TestMode` 下需要容错，避免事件/Neow 初始化因为本地化表缺失崩掉。
- `Shuriken`：上游实现没有把 mid-turn 计数标成 `[SavedProperty]`，会导致 save/load 后计数丢失；compat 版补了这个标记。

## 3. runtime patch / bootstrap 现状

当前工程已经不再保留 runtime Harmony patch 链路：

- `HeadlessHarmonyBootstrap.cs` 已下线
- `Program.cs` 不再在启动时尝试 `ApplyPatches()`
- 当前 host 不再保留自定义 runtime patch 代码；`Lib.Harmony` 仅作为上游 `ModManager` 的编译依赖保留

也就是说，这一轮验收通过**完全不依赖 Harmony 正在生效**，兼容性来自：

- `SrcCompat/Source01032`
- `SrcCompat/AutoGenerated`
- `HeadlessSim` 内的小型编译期 shim / stub

## 4. 继续保留的小 shim / stub

这类属于编译期适配，不是游戏逻辑 patch：

- `STS2AI/ENV/Sim/HeadlessSim/MigrationsCompat.cs`
- `STS2AI/ENV/Sim/HeadlessSim/ManualNodeAugments.cs`
- `STS2AI/ENV/Sim/HeadlessSim/ManualDebugAndPoolStubs.cs`
- `STS2AI/ENV/Sim/GodotSharpStub/src/*.cs`

# 本轮关键修复

## 1. `headless-binary` 协议恢复

Python 验证脚本原先把 host 以 `bin` 启动，却用默认 `proto` 协议的 `BinaryBackedFullRunClient` 去连，导致 `headless-binary` 看起来像随机断线。

已修复：

- `STS2AI/Python/verify_save_load.py`
- `STS2AI/Python/test_simulator_consistency.py`

两处都显式指定了 `protocol="bin"`。

## 2. binary transport 不再吞掉 `treasure/card_select/combat_rewards`

`Program.cs` 原先没有把部分需要 agent 决策的状态放进 `DecisionStateTypes`，binary 模式会自动继续往前走，导致状态被跳过。

已修复：

- `STS2AI/ENV/Sim/HeadlessSim/Program.cs`

新增决策态：

- `combat_rewards`
- `card_select`
- `relic_select`
- `treasure`

## 3. mid-combat save/load 的重复怪物恢复修正

原先敌人恢复按 `CombatId or ModelId` 做 `FirstOrDefault`，重复怪物时会把第一只匹配多次，导致 HP/MaxHP 恢复错位。

已修复：

- `STS2AI/ENV/Sim/HeadlessSim/Simulation/FullRunSimulatorRuntimeFacade.cs`
- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Rooms/CombatRoom.cs`

现在都改成了“消费式匹配”：

- 先优先按 `CombatId`
- 再 fallback 到 `ModelId`
- 每匹配一次就从剩余列表移除

## 4. `Shuriken` mid-turn 计数恢复

最后一条 combat parity 差异来自 `Shuriken`：

- save 前 counter = `2`
- load 后 counter = `0`

根因是上游 `Shuriken` 的 `AttacksPlayedThisTurn` 没有 `[SavedProperty]`。

已修复：

- `STS2AI/ENV/Sim/SrcCompat/Source01032/Core/Models/Relics/Shuriken.cs`
- `STS2AI/ENV/Sim/HeadlessSim/HeadlessSim.csproj`

现在 host 会排除上游 `src/Core/Models/Relics/Shuriken.cs`，改编译 compat 版。

## 5. 非战斗目标态驱动和验证脚本修正

为保证 `rest_site/shop/treasure/game_over` 的 save/load 验收稳定命中，本轮还修了测试脚本：

- `STS2AI/Python/verify_save_load.py`
  - map 状态现在会优先按 `map.next_options` 选择能直达目标态的节点
  - 非战斗 exact save/load 种子集已换成当前可稳定命中的集合
- `STS2AI/Python/tools/saveload_combat_parity.py`
  - 修正 `sys.path`，确保脚本能直接运行
- `STS2AI/Python/test_simulator_consistency.py`
  - 允许 `card_select -> event/rest_site/shop`
  - 这符合当前 full-run 非战斗选牌流，之前属于测试白名单过旧
