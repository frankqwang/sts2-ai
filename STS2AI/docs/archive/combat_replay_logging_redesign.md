# Combat Replay 日志重设计

## 目标

当前 replay 适合机器 grep，不适合人工做后期复盘，尤其不利于分析：

- 牌序是否合理
- 该不该先防还是先打
- 药水是否用早了
- 敌人意图变化是否被读懂
- 非战斗路线为什么走成这样

下一版日志建议保持两层输出：

1. `raw trace`
   保留现有紧凑英文格式，方便兼容旧脚本与快速 grep。
2. `zh trace`
   新增中文详细日志，服务人工复盘。

## 落地原则

### 1. 一步两行，而不是一行塞满

以战斗步为例，建议拆成：

- `上下文行`
- `决策行`
- `结果行`

示例：

```text
[第43步][战斗][我方回合]
我方：70/80 血，5 格挡，0 能量
手牌：防御(1)，打击(1)，打击(1)
敌方：海蛇朋克 32/32，意图 攻击 11x1

决策：使用药水 -> 力量药水
模型：value=0.62，logp=-0.07，权重=1.50，标签=药水决策
候选：使用药水 93% | 结束回合 7%

结果：敌人血量 32 -> 12；我方血量 70 -> 70；格挡 5 -> 5；能量 0 -> 0
下一拍意图：海蛇朋克 攻击 11x1
```

### 2. 名称解析优先级固定

日志里的卡牌名、怪物名、事件名、商店物品名，统一按这个顺序解析：

1. 状态里自带的显示字段：`label/title/name/description`
2. 游戏 API 直接透传的本地化文案
3. `Skada` 数据库里的 `name_zh`
4. token prettify，例如 `STRIKE_IRONCLAD -> Strike Ironclad`

这样可以兼容：

- binary pipe 只有 ID 的情况
- 高层 API 有显示名的情况
- 后续 transport 升级后自动吃到更好的本地化字段

### 3. 必须记录 pre_state -> post_state 的差分

后期分析最缺的是“执行后发生了什么”。建议每步都显式落：

- 我方血量变化
- 我方格挡变化
- 我方能量变化
- 目标敌人血量变化
- 其他敌人血量变化
- 状态变化（易伤、虚弱、力量、护甲、毒等）
- 是否击杀
- 是否抽牌 / 弃牌 / 消耗 / 生成牌

### 4. 回合级摘要要独立

建议每个玩家回合结束后追加一段摘要：

- 本回合打了哪些牌
- 总计造成多少预估伤害
- 总计获得多少格挡
- 用了几瓶药
- 是否提前结束回合

这对牌序复盘价值很高。

## 建议新增的日志类型

### 战斗开始

建议补：

- 房间类型（普通 / 精英 / Boss）
- 起始血量
- 敌人列表
- 药水栏
- 关键遗物

### 战斗步

建议字段：

- 步号
- 回合号
- 行动来源：`nn / mcts / warmup / auto`
- 选中的动作
- 候选 Top-K
- hard-state 标签
- 执行前上下文
- 执行后差分

### 敌人回合

当前 replay 基本看不到“敌人实际做了什么”。建议补：

- 哪个敌人出手
- 实际打了多少伤害
- 是否加 buff / debuff
- 玩家受到的总伤害

### 战斗结束

建议补：

- 胜 / 负
- 结束时血量
- 累计掉血
- 累计药水使用
- 累计回合数
- 关键坏模式计数

## 非战斗日志建议

### 地图

不要只写 `map: monster`。建议写：

- 当前层
- 当前分叉候选
- 选择的节点类型
- 若开启 `act1_no_elite_routes`，标明是否触发 override
- 当前路径摘要：到 Boss 还剩多少层、未来可能的火堆/商店/精英数量

### 商店

建议按“进入商店 -> 每个购买/删牌 -> 离开商店”三段写：

- 当前金币
- 可买物
- 实际买了什么
- 是否直接空店离开

### 卡奖

建议写：

- 候选三张
- 最终选中/跳过
- 当前牌组大类统计（攻击/防御/启动/过牌）

## 文件组织建议

建议一个 episode 两份文件：

- `i02200_e031_DEA_f12.txt`
  现有 raw trace
- `i02200_e031_DEA_f12.zh.txt`
  中文详细 trace

这样不会破坏旧脚本。

## 与数据挖掘脚本的配合

日志要为后处理让路，所以关键字段要稳定：

- `room_type`
- `enemy_group`
- `chosen_action`
- `target_enemy`
- `damage_delta`
- `block_delta`
- `energy_delta`
- `potion_use`
- `repeat_count`
- `route_choice`
- `shop_action`
- `card_reward_choice`

后续 replay 分析脚本就可以直接做：

- 早死怪物 Top
- 特定怪的错误牌序回放
- 药水滥用场景聚类
- 进入商店但空手离开的比例
- 卡奖跳过与死亡层数关联

## 推荐实施顺序

1. 先保留现有 raw trace，不动旧格式。
2. 增加中文详细 replay。
3. 先做战斗差分，再做非战斗详细日志。
4. 最后再补完整本地化名称解析。
